# E-commerce: средний чек по географии и прогноз повторных покупок

Анализ транзакций онлайн-магазина: проверяю, отличается ли средний чек у клиентов из Великобритании и из других стран, и строю модель, которая предсказывает, сделает ли клиент повторную покупку.

## Данные

Публичный датасет [Online Retail](https://www.kaggle.com/datasets/carrie1/ecommerce-data): транзакции британского интернет-магазина за 2010–2011. Чтобы запустить ноутбук, положите `data.csv` рядом с ним (в репозиторий файл не входит).

## Что сделано

1. **Очистка.** Убрал строки без `CustomerID` и с неположительными количеством или ценой (возвраты и отмены).
2. **Средний чек UK против остальных стран.** Агрегировал данные до клиента и сравнил две группы t-критерием Уэлча: группы разного размера и с разной дисперсией. Разница значима, p < 0,001. Распределения показал через KDE.
3. **Прогноз повторной покупки.** Построил RFM-признаки. Целевая переменная — больше одного заказа. Frequency и Monetary в модель не брал, они напрямую связаны с целевой переменной. Случайный лес на Recency и среднем чеке дал ROC-AUC около 0,79.

## Выводы

- У международных клиентов средний чек выше, у них длиннее хвост крупных заказов. Стоит посчитать, окупается ли их привлечение с учётом доставки.
- По истории покупок можно ранжировать клиентов по вероятности вернуться и адресно отправлять удерживающие предложения.

## Ограничения и что бы я улучшил

- Recency считается по всему периоду, включая саму повторную покупку, то есть частично содержит ответ. Корректнее разбить период по дате: признаки до отсечки, целевая переменная после.
- Средний чек в тесте считается по строкам транзакций, а не по заказам. Правильнее сначала сложить строки внутри `InvoiceNo`.
- Чеки тяжелохвостые: для устойчивости вывода стоит добавить критерий Манна–Уитни или бутстреп.
